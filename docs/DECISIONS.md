| 2026-10-16 | PII redaction uses Presidio with offline recognizers only: regex recognizers for phone and email, Presidio's credit-card and IBAN recognizers, and a per-account deny list (name, short name, contacts, phone). No spaCy model is loaded. | Presidio's default spaCy NLP engine and its phonenumbers/tldextract recognizers. | huggingface.co is blocked (Appendix A); Presidio's phone recognizer rejects the reserved 555 numbers we seed, and its email recognizer downloads the public-suffix list. |
| 2026-10-16 | The contact window closes for new sends at 20:50 local (10-minute buffer before 21:00). | Allow sends until 21:00. | FR-5 example: an approval at 20:55 local must be deferred to 08:00. |
| 2026-10-16 | Compliance amount and link checks fail closed. Every number must be an invoice number, date or time, URL part, identifier, small count (≤ 31) or the account name; otherwise it must equal an open invoice amount or the open total in the invoice currency. Any host not on the allowlist is flagged. | Only check numbers that have a currency marker; only check known TLDs. | M1 review blockers: the fail-open versions let "999 dollars", "$1k", "goo.gl/x" through. |
| 2026-10-16 | The STOP confirmation SMS is the only message sent without an approval record. It is one per opt-out (key `stop:<tenant>:<phone>`), comes from a fixed template and carries no collections content. | Route the confirmation through approval. | Opt-out confirmations are expected immediately; blocking them on a human would delay a regulatory duty. |
| 2026-10-16 | SMS send is at-most-once across crashes. The `messages` row (key `sms:<case_id>:<draft_version>`) is inserted before the Twilio call. If a redelivery finds the row without a provider SID, it marks it `failed / unknown_after_restart` and schedules a `send_retry` follow-up instead of resending. | Resend on redelivery. | Twilio has no idempotency key, so a blind resend could text the debtor twice. |
| 2026-10-16 | Auto-approval applies only when the NBA came from the model (`source == "llm"`) and the policy matches (`remind`, ≤ the max in USD with EUR at the scoring rate, confidence ≥ the minimum, clean post-check). Supervisors can only tighten the environment ceiling. | Allow auto-approval of rules or fallback decisions. | NFR-11: fallback output must always reach a human. |
| 2026-10-16 | A case whose NBA output is invalid twice ends with status `requires_analyst` (reason `nba_invalid_output`); the analyst starts a new case after reviewing. | An extra interrupt in which the analyst picks the action. | Keeps the graph and API surface small; the console shows the reason. |
| 2026-10-16 | The reply graph runs without a checkpointer. Its state lives in `messages` and `promises` (unique `ptp:<tenant>:<MessageSid>`), and every node is idempotent. The case graph is resumed from the reply graph with `resume_case {kind: await_reply}`. | Checkpoint the reply graph too. | A reply has no human pause, and redelivery is handled by the database keys. |
| 2026-10-16 | Claude API calls to `claude-opus-5-5` send server-side refusal fallbacks (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`); Haiku routes and Bedrock do not. | No fallbacks; client middleware on Bedrock. | claude-api skill default for Opus 5.5; on Bedrock a refusal falls back to the deterministic rules or templates (ADR 0002). |
| 2026-10-16 | import-linter's provider contract allows indirect imports: only direct imports of `anthropic` / `langchain_aws` outside `collections_copilot.llm` are forbidden. | Forbid transitive imports. | Every caller of the gateway would otherwise violate it; the rule is about who talks to the SDK. |
| 2026-10-16 | Compose publishes host ports on `127.0.0.1` only, and `ledger-mcp` publishes none: it trusts `_meta.mcpgw.tenant`, so only the gateway may reach it. Mailpit uses 8346 for SMTP and 8351 for its UI. | Publish on all interfaces; publish the ledger port. | M0/M1 review findings; §16.1 lists one Mailpit port, and the UI needed a second one in range. |
| 2026-10-16 | The gateway dev issuer (8349) is off unless `MCPGW_DEV_ISSUER=true` (set in compose and `.env.example`); JWTs need `iat` and a trusted `iss`. | Dev issuer on by default. | M0 review: an unauthenticated token endpoint must never be on by accident. |
| 2026-10-16 | Ingest never reopens a disputed invoice when a re-imported aging file says `open`. Upserts use `ON CONFLICT`; the file hash is claimed in a savepoint; rows are applied in a stable order. | Let the latest file win. | M1 review: a re-import would otherwise resume reminders on disputed invoices, and concurrent ingests raced or deadlocked. |
| 2026-10-16 | `REPOS = Depends(get_repos, scope="function")`: the unit of work commits before the response is sent. | FastAPI's default request-scoped yield dependency. | M1 review: a 2xx could otherwise be returned for a transaction that later failed. |
| 2026-10-16 | Offline evals run with `FakeLLM`: transparent keyword heuristics plus request-keyed cassettes. Offline numbers measure the pipeline, guardrails and fallbacks, not model quality; live numbers come only from `make eval-live`. | Report offline numbers as model quality. | Honesty rule (§0.6); `docs/evaluation.md` (T-50) must say this next to every offline number. |
| 2026-10-16 | Every send re-reads a snapshot from the database: case status, the draft row and its approval record for that exact version, invoices, opt-out, 7-day contacts and the contact flag. The SMS body is the stored draft row, and a re-run of `draft` reuses that row. | Trust the checkpointed state. | M2 reviews: a dispute or STOP between approval and a deferred send still sent a reminder; a crash between saving and checkpointing a draft could send text that differs from the approved row. |
| 2026-10-16 | A closed or failed case is final: case status updates from graph nodes never change it (`CasesRepo.set_unless_closed`). | Let nodes set any status. | A resumed node re-runs from its start and reopened a case STOP had closed (caught by `test_approval_on_closed_case_closes_without_send`). |
| 2026-10-16 | Auto-approval fails closed when the account currency has no scoring rate or open invoices mix currencies. | Treat unknown currencies 1:1 as USD. | M2 review blocker: GBP 450 (≈ USD 570) was auto-approved as "USD 450". |
| 2026-10-16 | STOP by rule: the whole message is a keyword; "unsubscribe"/"STOPALL"/"opt out"/"darme de baja" anywhere; or a request to stop contacting ("please stop texting me", "dejen de escribirme"). Ambiguous words inside longer messages ("End of month", "Cancel the invoice") go to the classifier, which can still label `stop`. | First keyword word plus up to four words. | M2 reviews: the old rule missed "Please stop texting me" and opted out "End of month". |
| 2026-10-16 | Reply side effects run once: each handler applies them and marks the inbound message `handled` in one transaction; a stored classification is reused on redelivery. The STOP confirmation is an outbound `messages` row (`stop:<tenant>:<phone>`) written with the opt-out and sent from that row, never resent once attempted. | Rely on each handler being naturally idempotent. | M2 review: redelivery duplicated follow-ups, notes, audits and model calls; a crash lost the confirmation. |
| 2026-10-16 | Twilio sends are retried only after connect errors, 429 or 5xx. Read timeouts and dropped connections mean "outcome unknown": the message is marked failed with a follow-up, never resent. | Retry every transport error. | Twilio `Messages.json` does not honour idempotency tokens, so a resend after a read timeout can text the debtor twice. |
| 2026-10-16 | The worker serialises each case (and each promise retry) with `pg_advisory_xact_lock(hashtextextended(key, 0))` held for the whole run; a resume must name the interrupt kind. | Rely on the checkpoint alone. | M2 review: two concurrent deliveries of one case raced, so one run marked the other's in-flight message failed. |
| 2026-10-16 | A send whose outcome is unknown (read timeout, 500/502/504, unreadable 2xx, crash after the claim) is marked failed, never resent, and still counted in `contact_log` for the 7-day cap. Only connect errors, 429 and 503 are retried. | Count only confirmed sends. | M2 re-review: the cap failed open when Twilio delivered a message whose response was lost. |
| 2026-10-16 | An approved draft that bounces back to a human (final post-check fails, or an auto-approval no longer matches the tightened policy at send time) becomes a new pending draft version with the same text, so the approval API can decide on it. | Re-interrupt on the approved version. | M2 re-review: the API answered 409 `already_decided` and the case was stuck. |
| 2026-10-16 | The worker's per-case advisory lock holds one pooled connection idle in a transaction for the whole run. The worker's database role must not set `idle_in_transaction_session_timeout`; the pool (10 + 10 overflow) is sized above `CC_WORKER_CONCURRENCY` (8). | A lease row with heartbeats. | Simplest correct serialisation; the caveat is recorded for the RDS parameter group (T-45). |
