# Known limitations

What is not done, or done with a documented compromise.

| Area | Limitation | Why / mitigation |
|---|---|---|
| Sibling dependencies | mcp-gateway is consumed through a contract-subset fallback in `third_party/mcp-gateway` because its `v0.1.0` tag and image do not exist yet. evalgate is the published `v0.1.0` (git tag, dev dependency). | Switch compose and Terraform to the published gateway when it exists. |
| Eval engine | evalgate v0.1.0 has no corpus or subset metrics, so `collections_copilot.evals.engine` computes macro-F1 and the scoped recalls on top of its per-case scores; the published GitHub Action and `evalgate run` alone report plain means. The tone calibration rows predate evalgate's `label_row.v1` and are read by the repository (frozen dataset). | Propose corpus and scoped metrics upstream; a `tone_calibration.v2` in the published label format. |
| Data model | Child tables reference parents by `id` only; there are no composite `(tenant_id, id)` foreign keys, so the database alone does not stop a row from pointing at another tenant's parent. | Every write goes through tenant-scoped repositories that take the tenant from the authenticated principal (`tests/integration/db/test_tenant_scoping.py`). Composite FKs are a hardening follow-up. |
| Audit | The hash chain detects modified or reordered rows, but deleting trailing events with the trigger disabled (database owner) is only detectable if the head `(seq, hash)` was exported earlier. | Runbook step: export the head hash daily with `cc audit verify`; an external anchor (e.g. S3 Object Lock) is a production follow-up. |
| Seed loader | Reloading after the gen.v1 digest changes appends notes again instead of replacing them. | The digest is stable for seed 4242; a changed generator needs `make clean` first. |
| Ingest | Aging re-imports never reopen a disputed invoice; there is no API yet to resolve a dispute explicitly. | Disputes are cleared in the source ERP; resolving them in the console is out of scope. |
| Redaction | Contact-person names are redacted only when passed as `AccountPII.contacts`; the data model has no contact-name field yet, so a person named only inside a free-text note is not redacted. Phone numbers (grouped, parenthesised and plain 9–15 digit forms, the account's own in any spacing; the account's own invoice numbers and reference are kept, but another account's 9–15 digit identifier in a note is redacted, and so is a whole amount written with dots or spaces as thousands separators and no decimals, such as `100.000.000`; a middle dot is not a separator, and a third-party number written straight after a digit and a separator, such as `ref 1/555-000-1234`, is taken for part of a date or amount and kept), e-mails, cards, IBANs and the account name (in its escaped forms too) are. | The synthetic notes contain no person names (`tests/unit/llm/test_pii_spy.py`); a contacts field in ingest is a follow-up. |
| SMS routing | All tenants share one sending number locally, so a reply from a number that several tenants texted recently cannot be attributed and is not routed (each tenant is told through a `reply.unattributed` audit event). STOP is always applied in every tenant. | Production gives each tenant its own Twilio number or Messaging Service and routes inbound by `To`; per-tenant sending numbers are not modelled in the code or in `infra/terraform` yet (follow-up). |
| Webhooks | The fallback gateway signs `{timestamp}.{body}` (`X-MCPGW-Timestamp`) and the API refuses events older than 300 s; the published mcp-gateway must do the same. Replays inside the window are answered without new audit rows (deduplicated by `approval_id`). Twilio does not retry inbound webhooks on 5xx by default, so the scheduler re-enqueues replies still `received` after 2 minutes. | Until the published gateway signs timestamps, keep the fallback image. |
| SSE | Each API process caps a user at `CC_SSE_STREAMS_PER_USER` (5) concurrent progress streams (429 beyond that), served from their own Redis pool (`CC_SSE_MAX_CONNECTIONS`, 200); each stream ends when its access token expires. | The counter is per process; see "Progress streams". |
| Ops metrics | The DLQ depth card is platform-wide (`dlq_scope: "platform"`): the dead-letter queues are shared by all tenants. | Per-tenant DLQs are not planned. |
| Evals | Offline numbers measure the pipeline and guardrails with the keyword FakeLLM, on templated synthetic data whose dev and test splits share templates: they are not estimates of model quality or of generalisation. `next_best_action.v1` does not spell out the numeric house thresholds the labels use for notes without a signal. | `make eval-live` measures a real model within budget; a v2 prompt stating the thresholds is a follow-up if live accuracy needs it. |
| Langfuse | A `langfuse` compose profile (8393) is not built: Langfuse v2 does not ingest OTLP, and v3 needs ClickHouse besides Postgres, Redis and S3. Traces go to Jaeger in profile `observability`. | Add Langfuse v3 with its OTLP endpoint as an extra exporter. |
| Personal names to the model | Person names inside notes and replies reach the provider: redaction covers the account's own name and phone, contact-data patterns and cards, but there is no offline person-name recogniser (docs/security.md, residual risks). | An offline name recogniser and CRM contact lists as a deny list; person-name probes in a `pii_leaked` eval dataset v2. |
| Agent token scopes | In KMS mode the API and the worker share one signing key and choose their own scopes; the gateway verifies them against the key the API publishes at `/.well-known/agent-jwks.json`. | One key per subject and a gateway-side subject-to-scope map. |
| Upload size | Presigned PUT URLs do not sign the object size; the API reads at most the limit of the exact version it checked, so oversized objects are refused, but storage can still receive them. | A presigned POST with a `content-length-range` policy. |
| Rate limits without Redis | The per-user and per-IP limits let requests through while Redis is down (idempotency fails closed instead). | A local in-process fallback bucket. |
| Local network isolation | Compose containers can reach the internet; nothing calls out except the configured providers, but it is not enforced. Every runtime image contains all workspace packages. | An internal-only compose network plus per-target images that install only their package. |
| Trace root | The BFF sends a `traceparent` but exports no span of its own, so Jaeger shows the API's server span with a missing parent. | Add the OpenTelemetry JS SDK to the BFF. |
| Terraform scope | envs/dev has no ElastiCache module: `CC_REDIS_URL` is a secret pointing at a Redis created separately. The mcp-gateway service runs this repository's gateway build from ECR until the upstream image is published; `mcp_gateway_image` switches it. The configuration is validated and tested with a mock provider only; it has never been planned against an account. | An `elasticache` module (TLS, auth token, KMS); publish the gateway image and set `mcp_gateway_image`; a plan with the GitHub plan role on `main`. |
| e2e | The Playwright suite runs against the live seeded stack and needs at least one account inside its 08:00–21:00 local window right now; between about 04:00 and 06:00 UTC no seeded zone is (Madrid, Canary and the US zones), and the helper says so. | A fixture tenant in a far-west zone, or a test clock in the API, is a follow-up. |
| BFF session | The single-flight refresh map lives in one BFF process, so several replicas need sticky sessions or a shared store. Logout clears the cookie and calls the issuer's logout but does not revoke the refresh token. | One web task locally; ALB stickiness or a Redis map, plus token revocation, when scaled out. |
| Console labels | The queue's next-best-action chip says "AI draft" for decisions made by the deterministic rules (accounts without notes), because the case does not store the decision source yet; fallbacks say "Template". | Store `nba_source` on the case (follow-up). Drafts and replies already show model, rule, template or analyst. |
| Performance | NFR-1 is met with 4 API processes on a host with 4 CPUs that also runs k6 and Postgres: about 9–10 ms of CPU per request and 0.64–0.79 ms per ORM query (in-process probe, 2026-10-17, see docs/DECISIONS.md). With keep-alive connections the account p95 sits near its 200 ms budget (179.05 and 207.94 ms in two `make bench` runs on 2026-10-17; 174.41 ms with `noConnectionReuse` on 2026-10-18) Later `make bench` runs on the same day were slower: the account p95 was 274.77 ms at `180ca64` and 281.09 ms at `dde18c3`, the commit that had measured 174.41 ms that morning, so NFR-1's account budget is not met there. On 2026-10-19 (macOS host, Docker Desktop, `make bench` at `a16aef7`) the account p95 was 254.16 ms and the queue p95 218.43 ms (budget 300 ms, met); NFR-2 (p95 127 ms) and NFR-4 (29.8 s) were met. | Fewer queries per detail page, Core rows for the queue page, or a reverse proxy that balances per request. In AWS, CPU autoscaling adds tasks. |
| Progress streams | The 5-per-user SSE limit (`CC_SSE_STREAMS_PER_USER`) and the Redis pools are per API process, so with `CC_API_WORKERS=4` in compose a user can hold up to 20 streams. | Move the counter to Redis if the limit must be global. |
| Identity (AWS) | Cognito threat protection needs the Plus tier and is not enabled; MFA is required. Bedrock model ids must start with `anthropic.` (a variable validation), which rules out cross-region inference profiles such as `us.anthropic.…`. | Add a profile variable and the multi-region model ARNs when a model needs a profile. |
| Edge and network (AWS) | ALB access logs are off by default (`access_logs_bucket = null`; ALB logs need SSE-S3, not the data key). The S3 gateway endpoint has no endpoint policy, because ECR layers come from AWS-owned buckets. Any workflow on `main` may assume the plan role (the sub claim is the branch). | Add a logs bucket, an endpoint policy listing the ECR layer buckets, and a protected environment in the sub claim for production. |
| Notifications (AWS) | Supervisor e-mail needs an SMTP relay (`smtp_host`, SES SMTP for example); the api and worker may reach it on `smtp_port`, but the notifier sends without authentication or STARTTLS. | Add SMTP credentials and TLS before relying on e-mail in AWS. |
| ECS networking (AWS) | Whether the Service Connect proxy in ledger-mcp and mcp-gateway (no internet egress) needs an ECS control-plane endpoint is not verified; the configuration has never been planned against an account. | Check on the first plan or deploy; add an `ecs` interface endpoint if the proxy cannot register. |
| Compliance follow-ups | The 3-per-7-days cap counts per account, not per phone number, so two accounts of one tenant sharing a number can receive up to 6 SMS in 7 days. A supervisor's promise approval checks that an invoice is still open but does not re-run the promise checks (a partly paid balance or a passed date). The gateway's USD 5,000 threshold is 500,000 minor units in any currency. The static send-site test matches receivers named `sms`; a ledger-write pin does not exist yet. The 7-day cap reached between approval and a deferred send is checked at send time but has no dedicated test. | Count contacts by `(tenant, phone)`; re-run `promise_problems` at approval; currency-aware gateway policy; an import-linter contract for `SmsSender` and `record_promise_to_pay`. |
| Terraform follow-ups | The WAF common rule set also inspects Twilio webhook bodies, so a reply containing `../` or `<script` could be refused (403, not retried by Twilio). `CC_SMTP_FROM` and `CC_SUPERVISOR_EMAIL` are not set in envs/dev, so AWS uses the `.example` defaults. The plan role's data-read deny includes `lambda:GetFunction` and `kms:Decrypt`, which a plan against real state would need. KMS key policies for logs, SNS and CloudWatch use `GenerateDataKey*`; data-key grants have no `kms:ViaService` condition. RDS Enhanced Monitoring writes to the account's `RDSOSMetrics` log group without the customer key. Web runs 2 replicas without ALB stickiness (harmless while Cognito does not rotate refresh tokens). Service Connect hops are plain HTTP inside the VPC, and the runbook does not prescribe `sslmode=require` or `rediss://`. `public_hostname` has a default. | Scope the WAF body rules away from the webhook path; wire the two e-mail settings; narrow the deny; explicit KMS actions with `kms:ViaService`; Service Connect TLS (AWS Private CA). |
| Images | Runtime code in the Python images is owned by the runtime user (`--chown=app:app`); ECS mounts the root filesystem read-only, compose does not. | Copy as root-owned and run compose services with `read_only: true`. |
| Ledger outages | A write-back that hits an outage is retried six times over about two hours (`promise_write_back` follow-ups) and then fails with a supervisor notification; the retry does not re-run the promise checks, so a promise whose date passed during a long outage is still written. Retries before a supervisor hold share the budget with the write after approval; a reply redelivery racing a scheduled retry can add a second follow-up (the audit count still bounds the attempts); a persistent `-32047` after the last retry marks the promise failed although the upstream may have committed; the retry counter counts audit rows without an index on `(action, entity_id)`. | Re-validate the promise before each retry; skip a retry while one is pending (`pending_for_promise`); index the audit count. |
| Test numbers | The hook test's Spanish negative case (`+34 600 000 000`) is in an allocated mobile range; Spain has no fiction range (docs/DECISIONS.md). | Replace it if a reserved Spanish range is published. |
